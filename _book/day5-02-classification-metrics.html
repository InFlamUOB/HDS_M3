18  Exercise 5.2 — Classification metrics

Every cell on this page is a real R or Python cell, run against data/diabetes.csv. Open day5-02-classification-metrics.qmd in your editor and run them one at a time.

18.1 Objectives

  • Compute accuracy, sensitivity, specificity and AUC from predicted probabilities, in both languages, and say which rows each one looked at.
  • State the accuracy of the majority-class rule for a dataset before you fit anything, and report every later accuracy next to it.
  • Explain how a model can be a percentage point better than that rule, find one diabetic patient in eight, and still have an AUC well above chance.

18.2 Why this, here

Chapter 17 ended where the outcome stops being a number. The outcome here is pos or neg, so the residual is no longer a distance and every metric on this page is built instead from counts in a 2×2 table. The table has two error types, the two are not interchangeable in a clinic, and accuracy — the metric everybody reaches for first — adds them together with weights chosen by the prevalence of the disease rather than by anyone’s judgement.

The data is the diabetes screening extract you have used since Day 2; the split is 70/30 and stratified, which is what Chapter 7 argued for.

#>        [ 11, 136]])
WarningWhich class is the event is a decision, and the two languages ask for it differently

In R, yardstick treats the first level of the factor as the event, so factor(diabetes, levels = c("pos", "neg")) is load-bearing: drop it, neg becomes the event, and your sensitivity and specificity silently swap places. In Python the convention is that the event is coded 1, which is why the outcome is converted with == "pos" and why labels=[1, 0] is passed to confusion_matrix to get the same orientation as R’s.

Nothing warns you if you get this wrong. The symptom is a model that looks implausibly good at ruling out a common disease.

Now the metrics, on the rows the model was fitted to and on the held-out rows.

  • R
  • Python
class_metrics <- metric_set(accuracy, sens, yardstick::specificity, precision)

dplyr::bind_rows(
  class_metrics(augment(age_fit, train), truth = diabetes, estimate = .pred_class) |>
    dplyr::mutate(set = "train"),
  class_metrics(test_preds, truth = diabetes, estimate = .pred_class) |>
    dplyr::mutate(set = "test")
) |>
  tidyr::pivot_wider(id_cols = .metric, names_from = set, values_from = .estimate)
#> # A tibble: 4 × 3
#>   .metric     train  test
#>   <chr>       <dbl> <dbl>
#> 1 accuracy    0.618 0.654
#> 2 sens        0.128 0.119
#> 3 specificity 0.900 0.959
#> 4 precision   0.424 0.625
def scores(model, X, yy):
    pred = model.predict(X)
    return {"accuracy": accuracy_score(yy, pred),
            "sens":     recall_score(yy, pred),
            "spec":     recall_score(1 - yy, 1 - pred),
            "auc":      roc_auc_score(yy, model.predict_proba(X)[:, 1])}

pd.DataFrame({"train": scores(age_fit, X_tr, y_tr),
              "test":  scores(age_fit, X_te, y_te)})
#>              train      test
#> accuracy  0.627561  0.627706
#> sens      0.147959  0.107143
#> spec      0.903226  0.925170
#> auc       0.658545  0.698777
Notespec is not specificity

In R, writing spec inside metric_set() picks up readr::spec, the function that reports a column specification, and metric_set() fails with a message about mixing metric types. Write yardstick::specificity. This is the most common five-minute delay on this page.

18.4 Worked example — the ROC curve, which does not need a threshold

Everything above was computed after turning probabilities into classes at 0.5. That threshold is a separate decision from the model (Chapter 15). An ROC curve shows what the model can do at every threshold at once: each point is one threshold, plotting sensitivity against 1 − specificity.

  • R
  • Python
roc_curve(test_preds, truth = diabetes, .pred_pos) |>
  autoplot() +
  labs(title = "Age-only logistic model, test set")
roc_auc(test_preds, truth = diabetes, .pred_pos)
#> # A tibble: 1 × 3
#>   .metric .estimator .estimate
#>   <chr>   <chr>          <dbl>
#> 1 roc_auc binary         0.678

fig, ax = plt.subplots(figsize=(4.2, 3.6))
ax.plot(fpr, tpr)

The AUC is the area under that curve. It has one honest interpretation worth memorising: take one patient with diabetes and one without, at random; the AUC is the probability the model gives the diabetic patient the higher score. It is a statement about ranking, it never looks at the threshold, and 0.5 is the value you get by ranking at random.

18.7 Task 3 — A control: break the model on purpose

An AUC of 0.68 from one predictor is either a weak signal or no signal reported confidently. The way to tell is to destroy the signal and see what the machinery reports. Shuffle the training outcomes so that no predictor can carry information about them, refit the full model, and score it on the untouched test rows. Do it ten times, because one shuffle tells you nothing.

  • R
  • Python
# Replace every ______ below, then run this cell.
shuffled_auc <- function(seed) {
  set.seed(seed)
  train_shuf <- train |> dplyr::mutate(diabetes = ______(diabetes))
  f <- logistic_reg() |> set_engine("glm") |> fit(diabetes ~ ., data = train_shuf)
  roc_auc(augment(f, test), truth = diabetes, .pred_pos)$.estimate
}
aucs <- vapply(1:10, shuffled_auc, numeric(1))
round(range(aucs), 3)
TipStuck?

The shuffled AUCs do not sit on 0.5. Ours spanned roughly 0.28 to 0.74 across the two languages. That spread is the width of an AUC estimated on 231 patients when there is nothing to estimate, and it is the yardstick against which the age-only model’s 0.66–0.70 should be read.

18.8 The result that should bother you

On the held-out rows, the age-only model’s accuracy is about 0.63–0.65. The rule “predict neg for everybody” scores 0.636. In R’s split the model is 1.7 percentage points above that rule; in Python’s split it is 0.9 points below it. And the model’s sensitivity is around 0.11–0.12: of the 84 test patients who have diabetes, it identifies nine or ten.

Three steps.

  1. Accuracy is a weighted average of sensitivity and specificity, with the weights fixed by prevalence — here 36% and 64%. A model can raise its accuracy by abandoning the minority class entirely, and at a threshold of 0.5 a weak model does exactly that: it predicts neg for almost everyone, inherits the majority rule’s accuracy, and loses almost nothing.
  2. So an accuracy near the prevalence of the commonest class is not evidence of a working model. It is the signature of a model that has declined to make a decision. Always print the majority-class accuracy first; it costs one line and it is the only context in which the second line can be read.
  3. Yet the same model’s AUC is around 0.66–0.70, which is not nothing. AUC ignores the threshold and asks only whether diabetic patients are ranked above non-diabetic ones. There is a real but weak ordering in age; accuracy at 0.5 threw it away. Two metrics, same model, two conclusions — and both are correct answers to different questions.

The full model, by contrast, reaches a test AUC of about 0.78–0.84 and a sensitivity of 0.49–0.57. It is the sensitivity that moved, from one patient in eight to about one in two, and sensitivity is the number a screening programme would be commissioned on.

18.9 Reflection

  1. A paper reports 94% accuracy for a model detecting a condition with a prevalence of 5%. Write the one sentence you would put in your review.
  2. AUC does not change when you change the threshold, and accuracy does. Give a clinical situation where that makes AUC the right summary, and one where it makes AUC the wrong one.

18.10 Stretch

NoteStretch 1 — Make accuracy look excellent

Keep every neg patient and a random 10% of the pos patients, re-split, and refit the age-only model. Report accuracy. Then report sensitivity. You have changed nothing about the model or the predictors.

NoteStretch 2 — AUC is not everything either

Two models can share an AUC of 0.80 and disagree completely about which patients are highest risk. Fit the all-predictor model and a model using only glucose, compare their AUCs, then compare the ranks they assign to the twenty highest-risk test patients. Which of the two would you rather hand to a triage nurse?

NoteStretch 3 — Balanced accuracy

Compute (sensitivity + specificity) / 2 for both models. What does it score for the majority-class rule, and why is that the property that makes it worth reporting?

18.11 What you can and cannot now claim

Can: that you can evaluate a classifier honestly — against the majority-class rule, with both error types shown separately, and with AUC reported as a property of the ranking rather than of any decision.

Cannot: that the model you evaluated is the best one available, or that either of today’s models is flexible enough for this data. A logistic regression can only draw one straight boundary. Chapter 19 fits a model that can draw as many as it likes, which turns out to be the problem.
