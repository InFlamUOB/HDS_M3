22  Exercise 9.1 — Importance, and a column of pure noise

22.1 Objectives

  • Fit a random forest and read two different importance rankings off it.
  • State, for each measure, what it is a measure of and which question it answers.
  • Use a pure-noise control to decide how much of a ranking to believe.

22.2 Why this, here

Chapter 20 left you with a forest that predicts better than the logistic regression of Chapter 14 and cannot be read. The obvious next move is to ask the forest which variables it used. Every library will answer that question. The problem is that they answer different questions, give different rankings, and none of them will tell you so. We settle it the way you would settle any measurement question: by measuring something whose true value we already know.

22.3 The model we will spend the day explaining

We add one predictor that cannot possibly matter — a column of random numbers, drawn independently of everything else, named noise. It is not a trick on the model. It is a control on the importance measures: whatever any of them says about noise, we know the right answer is nothing.

  • R
  • Python
library(readr); library(dplyr); library(parsnip); library(rsample)
library(yardstick); library(vip); library(ggplot2)

set.seed(123)
dia <- read_csv("data/diabetes.csv", show_col_types = FALSE) |>
  mutate(diabetes = factor(diabetes, levels = c("neg", "pos")),
         noise    = round(rnorm(n()), 2))

split <- initial_split(dia, prop = 0.7, strata = diabetes)
train <- training(split)
test  <- testing(split)

rf_fit <- rand_forest(trees = 500, mtry = 3, min_n = 10) |>
  set_engine("ranger", importance = "impurity", seed = 123) |>
  set_mode("classification") |>
  fit(diabetes ~ ., data = train)

preds <- predict(rf_fit, test, type = "prob") |> bind_cols(test)
roc_auc(preds, truth = diabetes, .pred_pos, event_level = "second")
#> # A tibble: 1 × 3
#>   .metric .estimator .estimate
#>   <chr>   <chr>          <dbl>
#> 1 roc_auc binary         0.787
import numpy as np, pandas as pd
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import roc_auc_score
from sklearn.inspection import permutation_importance

dia = pd.read_csv("data/diabetes.csv")
y = (dia["diabetes"] == "pos").astype(int)
X = dia.drop(columns=["diabetes"]).copy()
X["noise"] = np.random.default_rng(42).normal(size=len(X)).round(2)

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=123, stratify=y)

rf = RandomForestClassifier(n_estimators=300, random_state=123).fit(X_train, y_train)
auc = roc_auc_score(y_test, rf.predict_proba(X_test)[:, 1])
round(auc, 3)
#> 0.756

Both forests score a test AUC in the high 0.7s. Note the event_level = "second" in the R call: the factor levels are neg, pos, and yardstick treats the first level as the event, so without that argument you would be scoring the model’s ability to detect absence of diabetes.

22.4 Measure 1 — impurity importance

Every split in every tree reduces Gini impurity by some amount. Impurity importance adds those reductions up, per variable, over the whole forest. It is free: the forest already computed it while fitting. It is also entirely internal — it is a summary of what happened inside the training rows, and no test data enters it anywhere.

  • Python

TipStuck?

The check wants the importances themselves, not the model. In R that is the object vi() returned; in Python it is the Series you built from feature_importances_. The check finds noise by name.

The check prints [fix]. That is not a mistake in your code. It is the check doing its job on a measure that has just handed a third of its top score to a column of random numbers.

22.6 Task 2 — Ask a different question

Permutation importance asks something else entirely: if I destroy this variable, how much worse does the model get? Shuffle one column of the test set, re-score, record the drop in AUC, put the column back, repeat. Nothing is refitted; the model is held fixed and the data is damaged.

Fill in the two blanks: which rows to permute, and which metric to score.

TipStuck?

Permutation importance needs rows the model has not been fitted on, and a metric to measure the damage with. You have both already: the held-out set, and the AUC you reported above. In Python the metric is a string scikit-learn recognises; in R it is a yardstick metric name.

This time the check passes. Under permutation the control is worth a few per cent of glucose at most, which is what zero looks like once sampling noise is added to it. Report which variables changed rank between the two measures.

WarningBelow the top two, the ordering is not real

In both languages glucose dominates and age is a distant second. Everything below that is a cluster of near-zero values whose spread across repeats is as large as the values themselves — noise finishes inside that cluster, in R slightly above zero and in Python slightly below it. Do not report a rank order within a cluster like that. Report the cluster.

22.7 The result that should bother you

Impurity importance put noise fifth of nine, ahead of blood pressure, insulin and triceps skinfold — three measurements a diabetes clinic actually takes. Reason it through in three steps.

  1. The forest is allowed to split on noise, and with mtry = 3 it is offered the chance about a third of the time. A continuous variable with 768 distinct-ish values offers a great many candidate split points, so by chance some of them separate the training rows well.
  2. Each of those lucky splits reduces training impurity, and impurity importance counts every one of them. Nothing in the measure asks whether the reduction survives on rows the forest has not seen.
  3. So impurity importance is a faithful description of how the forest was built. It is not evidence about which variables carry signal. Those are different claims, and only the second one is what anybody wants.

This is not an obscure edge case. It is the default output of feature_importances_ and of vip(), it appears in papers, and the control that exposes it costs one line.

22.8 Task 3 — Is the noise column doing any harm?

If impurity importance is right that noise matters, dropping it should hurt. Refit the forest without it and compare test AUC.

  fit(diabetes ~ ., data = ______)

  roc_auc(truth = diabetes, .pred_pos, event_level = "second")
# Replace every ______ below, then run this cell.
rf_clean = RandomForestClassifier(n_estimators=300, random_state=123).fit(
    X_train.drop(columns=______), y_train)
auc_clean = roc_auc_score(y_test, rf_clean.predict_proba(
    X_test.drop(columns=______))[:, 1])
print(round(auc_clean, 3), "versus", round(auc, 3), "with the noise column")

The AUC moves by about one point in the second decimal — in Python it goes up a little, in R down a little. That is the same size as the spread you get from refitting the forest with ten different seeds and changing nothing else, so it is not a difference at all. A variable that one importance measure ranked fifth of nine is worth nothing to the prediction.

22.9 Reflection

  1. Impurity importance and permutation importance disagreed. Write the sentence you would say to a clinical collaborator who asks which one is correct — without using the word “wrong”.
  2. Permutation importance is computed on held-out rows here. What would change if you computed it on the training rows instead, and which of the two would you report in a paper?
  3. You now have a control for importance. What would the equivalent control be for a claim that the model is well calibrated?

22.10 Stretch

NoteStretch 1 — Two controls, not one

Add a second control: a column of integers 1:n, a row identifier. It carries no information either, but it has one distinct value per patient. Where does impurity importance put it, and what does the comparison with noise tell you about which features that measure favours?

NoteStretch 2 — Correlated predictors break both measures

Add a copy of glucose with a little jitter, so the two columns are nearly identical. What happens to glucose’s permutation importance, and why? Write down the sentence a reader would wrongly conclude from the new ranking.

22.11 What you can and cannot now claim

Can: that for this forest, on these held-out rows, permuting glucose costs about 0.14 of AUC and permuting anything else costs almost nothing; and that a column known to be meaningless was ranked fifth of nine by the forest’s own built-in importance.

Cannot: anything about an individual patient. Both measures are averages over the whole test set, and an average over 231 people cannot tell you why the model said what it said about one of them — which is what Chapter 23 is for.
