2  Exercise 1.1 — Two languages, one analysis

45 minutes · work in pairs, one of you driving each language

Every cell on this page is a real R or Python cell. Open day1-01-two-languages.qmd in your editor and run them one at a time — the output printed here is what you should get. If a package is missing, see Appendix A.

2.1 Objectives

  • Read a .csv, filter rows, summarise by group, fit a linear model and draw a scatter plot, in either language, without a cheat sheet open.
  • Point at a number in your output and say whether it would be identical in the other language, and why.

2.2 Why both

R and Python encode two different ideas of what an analysis is. In R the unit is the data frame and the verbs act on whole columns; in Python the unit is the object and you call methods on it. Most differences you meet today follow from that one difference.

A difference worth noticing immediately: read_csv() guesses column types and tells you what it guessed; pd.read_csv() guesses and says nothing. A column of ages containing one entry of "unknown" becomes character in R, with a message, and object in pandas, in silence.

2.4 Filter, and summarise by group

This is where the two look least alike.

  • R
  • Python
library(dplyr)
los |>
  mutate(sev_band = if_else(Severity > 7, "high", "low")) |>
  group_by(sev_band) |>
  summarise(n = n(), mean_los = mean(LOS), .groups = "drop")
#> # A tibble: 2 × 3
#>   sev_band     n mean_los
#>   <chr>    <int>    <dbl>
#> 1 high       217     75.7
#> 2 low        783     63.1
(los
 .assign(sev_band=lambda d: (d["Severity"] > 7).map({True: "high", False: "low"}))
 .groupby("sev_band")["LOS"]
 .agg(n="size", mean_los="mean")
 .reset_index())
sev_band n mean_los
0 high 217 75.670601
1 low 783 63.146582

2.5 Fit a linear model

  • R
  • Python
fit_r <- lm(LOS ~ Age + Severity, data = los)
coef(fit_r)
#> (Intercept)         Age    Severity 
#>  -8.4057616   0.9330946   3.4352548
from sklearn.linear_model import LinearRegression
X = los[["Age", "Severity"]]     # 2-D: a frame, not a series
y = los["LOS"]                   # 1-D
fit_py = LinearRegression().fit(X, y)
fit_py.intercept_, fit_py.coef_
#> (np.float64(-8.40576161279266), array([0.93309456, 3.43525475]))

Two things differ here and only one matters. lm() returns a statistical summary — standard errors, residuals, an F test — because R’s linear model was written for inference; LinearRegression returns coefficients and a .predict() method, because scikit-learn’s was written for prediction. That is a difference in purpose. The coefficients themselves agree to every decimal you care to print, because both solve the same least-squares problem on the same rows. That is not a difference at all.

2.10 Task 4 — Find a difference that matters

Between you, find one place where the two languages genuinely give different results for the same instruction, and one where they only appear to. A sentence each. Somewhere to start: random number generation, how each handles a missing value inside mean(), and what happens when you index a frame with a number.

2.11 Stretch

NoteStretch 1 — parsnip, so that 1.2 feels familiar

Refit with parsnip, the part of tidymodels that standardises model fitting: linear_reg() |> set_engine("lm") |> fit(LOS ~ Age + Severity, data = los). The coefficients are identical, because set_engine("lm") means it is calling lm(). What tidymodels adds is one interface in front of many engines, which is what makes the pipeline in 1.2 swappable.

NoteStretch 2 — Make the same split in both languages

Draw an 80/20 split in R, write the row indices out, and reproduce the identical split in Python. This is tedious, and that is the lesson: cross-language reproducibility is not free, and the professional answer is to split once, in one language, and save the result.

2.12 What you can and cannot now claim

Can: that you can perform the five basic operations in both languages, and that the coefficients you obtained are a property of the data rather than of the software.

Cannot: anything about how well this model predicts. Every number here was computed on the same 1000 rows the model was fitted to. That is Chapter 3.
