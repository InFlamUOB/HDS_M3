Appendix E — Adding a day

A new teaching day is five files and a block of configuration. This chapter is the procedure.

E.1 1. Scaffold it

make day DAY=2 TITLE="Validation you can defend"

or, equivalently:

python3 scripts/new_day.py --day 2 --title "Validation you can defend" \
    --exercises resampling,metrics

That writes day2-00-overview.qmd, one chapter per exercise named, and day2-99-consolidation.qmd from _templates/exercise.qmd, and registers the part: block in _quarto.yml. Re-running it leaves existing files alone, so it is safe to use again when you add a fourth exercise to a day.

Chapter files live at the project root, named day<N>-<nn>-<slug>.qmd, so that data/los_data.csv is the correct path everywhere: in the chunk you run in Positron, in the rendered page, and in the script a student copies it into.

E.2 2. Check it before you publish

make check

scripts/check_cells.py catches the faults that render cleanly and then fail in front of a student: a task chunk missing eval: false, a worked answer outside the when-meta="show-solutions" block (which would publish it before the session), and a link to a chapter that does not exist. The publish workflow runs the same check, so a push with any of these fails before it reaches students.

E.3 3. Add any new data to the generator

Append to scripts/make_data.R; do not write a second script. One generator with one seed is what makes every student’s copy identical and every expected value quotable. New data files are published automatically, since project: resources: includes data/.

E.4 4. Add a check, if the exercise needs one

checks/checks.R and checks/checks.py are deliberately small. A new check wraps hds_check():

check_folds <- function(folds, n_expected = 5) {
  hds_check(paste0("there are ", n_expected, " folds"),
            nrow(folds) == n_expected,
            hint = "check the v = argument of vfold_cv()",
            detail = paste(nrow(folds), "folds"))
}

Write the Python twin at the same time. A check that exists in one language only quietly turns the booklet into a single-language course.

E.5 5. Build

quarto render                                      # student site  -> _book/
quarto render --profile instructor                 # staff copy    -> _book-instructor/
python3 scripts/make_worksheet.py --day 2 --profile student
quarto render print/day2-student.qmd --to typst    # printable worksheet

Only _book/ is published. The instructor profile writes elsewhere precisely so that publishing cannot leak solutions.

E.6 Writing the cells

You want How
a worked example, shown with its output a plain ```{r} or ```{python} chunk
a task for the student to fill in the same, plus #\| eval: false, with ______ where the answer goes
a hint a ::: {.callout-tip collapse="true"} block — name the function, never the line
the worked answer a ::: {.content-visible when-meta="show-solutions"} block containing an executed chunk

Two rules, each learnt the hard way.

  1. A task chunk must be eval: false. ______ is not valid code, so the render fails without it. make check catches it.
  2. Hints are always visible. A hint containing the answer line publishes the answer; name the functions instead.

E.7 Keeping the worksheet under twenty pages

scripts/make_worksheet.py drops solutions, hints, instructor blocks and browser-only notes, and flattens the R/Python tabs into labels, which is most of the saving. Day 1 comes out at 14 pages for students and 16 for staff. If a day runs long, the thing to cut is narrative, not tasks: move the discussion into a ::: {.web-only} block, where it stays on the site and leaves the paper.

E.8 The house structure, and why each piece is there

Element Purpose What breaks without it
Objectives as can-do statements the student can self-assess “I attended” substitutes for “I can”
Worked example with nothing hidden a correct pipeline seen before one is built students debug syntax instead of learning the idea
Numbered tasks with a stated deliverable unambiguous done-ness the strong students finish and the rest stall
Hint, behind a button unblocks without answering either hand-holding or silence
Check yourself catches silently wrong objects in seconds a plausible wrong number survives to the report
A control in every exercise belief in the method, not the output students trust pipelines because they ran
Instructor block, profile-gated answers, ranges, failures, timings the answers are either lost or published
Can and cannot claim scope discipline, and the hook to the next day exercises feel like unrelated notebooks

E.9 Two conventions worth keeping

Solutions go in solution: true cells and instructor commentary in content-visible when-profile="instructor", never in a collapsed callout. A collapsed callout still ships the text inside the student HTML, two clicks away in the page source.

Quote expected values as ranges. make_data.R is reproducible, but anyone who changes an n or adds a draw shifts the random stream downstream. “MAE ≈ 3.2–3.4 days” survives that; “MAE = 3.423” does not.
